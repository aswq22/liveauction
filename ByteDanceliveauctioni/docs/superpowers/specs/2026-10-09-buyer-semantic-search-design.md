# 买家生产级拍品语义检索设计

日期：2026-10-09
状态：用户于 2026-10-09 确认设计；进入实施计划阶段，尚未实施或完成生产验收。

## 1. 已确认需求与设计假设

用户确认：约 10 万拍品；默认搜索全平台公开拍品，允许限定直播间；支持口语、近义词和不完整描述。

目标示例：“给妈妈的生日礼物，三千以内，玉石类”“通勤戴的小巧耳饰”“正在拍的镯子”。同义表达应召回真实相关商品；明确预算、状态及直播间条件必须满足。模糊描述可以排序匹配，不能据此编造商品材质、真伪、证书或用途事实。

暂定容量目标为峰值 100 QPS，正常混合检索 P95 ≤ 800ms、P99 ≤ 1500ms。这些是待指定硬件、Embedding 配额和真实数据压测验证的验收目标，不是已有性能结论。语义服务故障时允许显式降级为词法检索；用户取消和请求超时必须停止下游工作。

本设计服务买家 H5 搜索与直播间找拍品，不扩展商家 Agent 的工具和业务写入权限。公开跨商家检索合法，但草稿、未发布库存、禁用商家和不可见直播间不能被返回。

## 2. 当前代码证据与缺口

- `internal/searchindex/worker.go`：默认 5 分钟轮询，只有内存时间游标；部分失败仍推进游标，失败项可能不再被处理。
- `internal/data/search_docs.go`：按 `updated_at > cursor` 扫描并限制批量，同一时间戳跨批可能漏项；商家/直播间变化未必更新拍品时间戳。
- `internal/searchindex/types.go` / `search_docs.go`：语义文本和 Hash 包含价格、状态、更新时间，使非语义变化重复触发 Embedding。
- `internal/searchindex/pgvector.go`：未创建 ANN 索引；查询没有返回实际距离、模型代际过滤或相关性门槛。
- `internal/service/ai.go`：向量召回后逐项回源；词法检索遍历公开房间与拍品；预算仅加减分，不是硬条件；按候选排名给分可能把无关商品推到结果前列。
- `ConsultBuyer`：列表链路还等待 LLM 生成回答，增加搜索延迟和故障依赖。已有结果白名单约束继续保留在问答功能中。
- `live-auction-user-h5/src/pages/SearchPage.tsx`：已有输入与结果入口，可以接入独立搜索契约。

## 3. 方案选择

1. 只修当前向量查询：工作量小，但不能解决中文词法召回、可靠同步、质量门槛和明确预算过滤，不满足本需求。
2. PostgreSQL + pgvector 混合检索：复用现有基础设施，增加 HNSW、中文词法索引、可靠任务和确定性结果。选用此方案，是否达到容量目标由压测判断。
3. 引入 OpenSearch/Elasticsearch 承载混合检索：可提供更完整的搜索运营能力，但新增集群、分析器与双存储运维；当前 10 万拍品先不增加该依赖。

## 4. 查询架构与职责

```text
H5 搜索请求
  → 参数校验、限流、查询归一化、明确约束解析
  → 中文词法召回 ─────────────┐
  → 查询 Embedding → HNSW 召回 ├→ RRF 融合、相关性门槛
                              └→ 批量权威数据读取
                                  → 可见性/状态/实时价格硬过滤
                                  → 稳定排序、有限候选补取
                                  → 真实拍品列表
```

业务层定义搜索、Embedding、索引与权威数据读取接口；data 层负责 SQL、Redis、任务和事务；service 层映射业务响应；server 层处理协议与请求治理。买家普通搜索不调用生成式 LLM。现有 AI 问答可消费同一搜索服务的真实结果，回答生成与列表搜索独立。

## 5. 搜索契约与产品行为

Proto 新增 `SearchBuyerLots`，HTTP `POST /api/buyer/lots/search`。与 H5 在同一实施阶段切换到新契约，不增加旧形状兼容分支。

请求字段：`query`、可选 `room_id`、可选 `min_price_amount` / `max_price_amount`、可选 `statuses`、`page_size`、可选 `cursor`。金额为人民币整数分；query 去除首尾空白后 1–256 Unicode 字符；page_size 默认 20、最多 50；仅接受公开业务状态。无效参数、金额溢出、非法状态和签名失效的 cursor 返回明确业务错误。

查询文本先做 Unicode 归一化、空白合并、拉丁大小写归一化。预算支持确定性解析“3000 元以内”“不超过三千”“预算 2k”等验收词表；纯商品型号或孤立数字不当成预算。显式筛选字段优先，无法可靠解析时保留原语义并返回未应用约束提示；绝不展示为已应用。查询中存在多个冲突预算返回需澄清错误。排除性要求仅在有明确领域规则时生成硬约束，否则原文参与语义检索并提示未严格应用，不能默默删去否定词。

响应包含：`results`、`applied_filters`、`mode`（HYBRID / LEXICAL）、`degraded_reason`、`next_cursor`、`result`。结果中的 ID、图片、标题、状态、价格、直播间链接均来自权威业务数据；匹配说明使用确定性证据，不生成商品属性。预算以返回瞬间的最新价格校验，UI 明示竞拍价格可能继续变化。

首屏可生成最长 2 分钟的有界结果快照，保存最多 200 个排好序的 ID；cursor 用 HMAC 绑定查询、范围、筛选、代际、快照和位置。后续页面仍重新验证每个商品，状态变化可以使页面变短；没有可靠总数时不返回伪造 total。缓存失效返回明确 cursor 过期，前端重新搜索。权限、价格和状态的权威回源失败返回依赖错误，不能表现为正常空结果。

H5 对搜索请求做取消和过期响应抑制；展示实际应用筛选、无结果及显式词法降级状态。输入、状态和分页契约均有测试。

## 6. 索引内容与模型代际

稳定语义文本只包含标题、描述、分类、标签和数据库已有的商品属性。Embedding Hash 仅覆盖该规范化文本、模板版本、模型版本和维度。价格、状态、直播间可见性、索引更新时间保存在筛选元数据中，变化时更新元数据，不重新生成向量。

保留现有 Embedding 供应方作为第一版集成对象，是否满足中文质量目标要用真实标注数据验证，不把供应方选择当作召回质量结论。响应校验条数、唯一且完整的 index、维度、非有限值及零向量；异常响应不得进入索引。

每个索引代际固定模型标识、供应方配置版本、维度和模板版本。数据库保存 active generation；每代使用独立的受白名单控制的表与索引，避免不同模型向量混搜。DDL 由显式迁移执行，生产启动只校验 schema 和版本。

新增 `hnsw (embedding vector_cosine_ops)`，以及公开标记、直播间、状态和词法检索索引。pgvector 版本固定到经验证的 ≥0.8 版本，镜像固定版本与 digest。全平台 ANN 查询设置事务局部 `ef_search`、迭代扫描和扫描上限；局部直播间候选很少时优先按索引筛选后精确排序，具体切换阈值由计划和压测校准。必须用 `EXPLAIN (ANALYZE, BUFFERS)` 验证实际计划，不把创建 HNSW 当作一定会使用 HNSW。

中文词法采用 Go 端一致的 Unicode 汉字二元组、拉丁词及版本化领域同义词词表，生成空格分隔 token 后使用 PostgreSQL `simple` 配置的 tsvector 和 GIN；query 使用相同 tokenizer 与 token 安全构造 tsquery。标题、分类与标签权重高于描述。拉丁商品名和型号额外使用 `pg_trgm` 索引进行有界模糊匹配。中文错别字能力以真实样本评测为准，不承诺任意错字均可识别。型号查询优先保留完整型号，避免分词丢失精确匹配。

## 7. 可靠索引同步

新增 MySQL 持久化搜索任务：任务 ID、拍品 ID、generation、语义 revision / metadata revision、类型、状态、重试次数、next_attempt_at、租约 token 和过期时间、错误码。商品创建、内容编辑、入队/开拍/结束/下架等提交事务中同步写任务。商家封禁、房间隐藏及角色撤销写有界分页的范围失效任务，覆盖该范围全部拍品。高频价格不触发 Embedding，仅走权威查询；元数据投影可合并，但显式公开性变化不能丢失。

worker 用 `FOR UPDATE SKIP LOCKED` 在短事务内领取任务，提交后调用供应方，避免网络操作长期占数据库锁。租约可续期；确认任务时校验租约 token 和任务 revision。领取任务后重新读取业务源，源已删除时写 tombstone。

PostgreSQL Upsert 按 source revision 条件更新，旧任务不能覆盖新内容。若最新内容已有语义修订但向量尚未完成，不拿旧向量冒充新内容；词法与元数据先更新，语义召回暂时不包含它。

先持久化 PostgreSQL 索引，再确认 MySQL 任务。跨数据库不宣称原子事务：宕机后任务重放，靠 revision 和幂等 Upsert 收敛。429 尊重 Retry-After，网络/5xx 使用有上限的指数退避与抖动，达到重试上限进入死信并告警；认证/模型配置错误立即告警，阻止循环重试。

后台对账与全量回填使用 `(updated_at, lot_id)` 复合游标并持久化；全量扫描、房间/账号变化和物理删除另行对账，不把单纯时间戳扫描当作完整变更捕获。对账负责补任务，不直接绕过 revision 写索引。首版新代际回填采用 ID keyset 分页与事务任务捕获并行；全部变更最终由任务收敛。

## 8. 混合召回、相关性与硬过滤

词法与向量通道并行执行，候选默认各 100 个，融合采用 RRF（初始常数 60）；候选、补取轮次和总耗时都有上限。RRF 只融合排名，不能代替相关性门槛。

向量通道保留真实距离，并使用由评测集校准的模型级门槛；词法通道保留真实命中 token 和原始排序分。无相关语义信号或词法证据的商品不能因“正在拍”而进入结果。状态、预算、房间是过滤条件，业务热度仅用于相关结果之间的有限排序。对开放性需求可以返回相关类别，不能把“语义像礼物”解释成数据库不存在的材质认证。

批量读取 MySQL 权属、商品与房间/账号可见性，并按现有运行态读取契约批量叠加 Redis 中最新价格和状态。每个结果确认拍品 room/main account 关系与当前公开状态；任意候选缓存命中也经过这一步。Redis 不可用而无法取得可信实时价格时，预算过滤搜索返回明确依赖错误，不用异步投影的旧价保证预算。

粗过滤后有效结果不足时在请求 deadline 内扩大召回，最多两轮、最多 400 个候选；继续不足返回较少结果，不用无关拍品填满。不可伪造同一时刻的平台全局一致快照：返回价格是该请求读取时的值，点击及出价仍由交易链路再次验证。

## 9. 延迟、缓存与故障治理

- 默认总 deadline 1500ms；初始 Embedding 子预算 450ms，查询和回源子预算各 200ms，剩余预算用于并行调度与有界补取；正常 P95 的 800ms 目标需实测。
- 查询向量缓存 key 包含规范化文本、模型与代际，初始 TTL 24 小时；有界本地 singleflight 合并同进程重复请求；Redis 故障时无缓存继续，但须受供应方并发上限保护。
- 候选 ID 缓存初始 TTL 10 秒，key 含全部筛选、范围及代际；永远不缓存权威校验后的价格和可见性作为最终事实。
- 分别限制客户端请求、Embedding 并发、DB 连接池与索引 worker；有限队列满时明确拒绝，避免 goroutine 与供应方账单无限增长。
- Embedding 超时/限流/熔断时返回带 mode 与原因的有索引词法结果；该能力降级是正式产品行为，不是旧实现兼容。pgvector 不可用且词法同库不可用时返回 SEARCH_UNAVAILABLE，绝不回退全表遍历 MySQL。
- 搜索启动配置缺失明确报错；搜索依赖的健康与核心交易 readiness 分别表达，不能因搜索故障停掉竞价，也不能把词法服务假报为混合检索健康。
- 新索引备份、恢复、DDL 验证、供应方密钥轮换与限额都有运行手册；外部模型只接收公开文本，限制日志保留和 query 内容，指标标签不包含 query/lot/room/user ID。

## 10. 可量化验收

构建至少 200 条真实中文查询的人工标注集，包含近义词、口语、错字、型号、预算、状态、限定直播间、否定约束、无相关商品、隐藏与已结束商品；查询语料与调参语料分离。以下是首版上线门槛，未达到则不称生产级完成：

- 搜索相关性：held-out Recall@50 ≥ 0.90，NDCG@10 ≥ 0.80；分别报告口语、型号、错字等子集结果，不能只看平均值。
- ANN 单独对比精确向量检索 top50，目标 ANN Recall@50 ≥ 0.95；与人工相关性指标分开计算。
- 所有硬条件测试通过；隐藏/草稿/禁用商家泄露为 0；无关查询不会默认返回热拍品。
- 正常内容变更索引新鲜度 P95 ≤ 30 秒；Embedding 长期故障显式告警与降级，恢复后任务可全部重放收敛。
- 10 万规模，持续 100 QPS 30 分钟与 200 QPS 5 分钟阶梯测试；记录硬件、供应方限额、缓存命中率和成本。100 QPS 正常混合模式 P95 ≤ 800ms、P99 ≤ 1500ms，系统错误率 <0.1%。冷缓存与热缓存分别报告，不能只以热缓存覆盖供应方延迟。
- 验证同时间戳分页、部分失败、worker 重启、多 worker 争抢、乱序任务、模型代际切换、商家/房间失效、删商品、429/5xx/超时、损坏向量、缓存失效、用户取消和无权限访问。
- 真 PostgreSQL/pgvector 与 MySQL 集成验证 SQL、迁移和执行计划；真实供应方抽样评测，确定性假向量只能用于协议与故障测试。

Prometheus 记录按阶段耗时、查询 mode、空结果率、词法/向量候选量、权威校验淘汰量、缓存命中、Embedding 调用/限流/费用估算、任务积压/最老任务年龄/死信与修订冲突。告警覆盖索引落后、错误率、降级率和池饱和。Click-through 等运营指标后续采集，首版不将曝光偏差当作相关性事实。

## 11. 实施边界与上线顺序

主要修改：搜索业务接口与独立 service、`searchindex`、`data/search_docs.go` 与新增任务仓储、受影响的商品/房间/账号事务点、Proto 和生成代码、server 注册、部署迁移、metrics、H5 SearchPage 与 API 适配、测试及运行手册。

当前工作区存在大量未提交用户改动，包含 `service/auction.go`、`server/http.go`、Agent/拍品业务代码与 H5 类型；实施计划必须逐项审核重叠，不覆盖、重置或顺手提交已有改动。本设计稿仅新增独立文档。

实施次序：契约与语料 → 可靠索引任务与语义/元数据拆分 → HNSW 与中文词法 → 搜索/过滤/治理 → H5 接入 → 真库集成与离线评测 → 10 万规模压测与故障恢复 → 新代际回填和对账 → 审核指标后启用。

部署前准备新代际，完成回填、索引构建与校验，再原子切 active generation；保留上一完整代际用于回滚。切换失败不删业务数据或旧索引；新 API 和 H5 同步部署，无旧协议适配。外部部署、生产密钥与生产数据迁移需要具体目标环境后再执行。
