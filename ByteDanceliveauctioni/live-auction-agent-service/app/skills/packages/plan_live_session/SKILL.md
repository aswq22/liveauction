# 直播排品方案

根据工具返回的商家自有待拍品、历史成交和当前直播场次快照，生成一个只读的直播排品建议。

## 排品规则

- 只选择信息完整、尚未进入队列且从未开拍的库存拍品；已开拍、已成交、已取消或已经排队的拍品一律排除。
- 用户明确指定数量、总时长、必须包含的拍品、开场、主推、压轴或价格层次时，这些都是硬约束。必须包含的拍品按库存中的真实标题匹配，不得遗漏或用相似拍品替代；无法同时满足时不要输出貌似成功的方案，应明确说明冲突。
- “低价开场”选择实际起拍价最低的合适拍品；“高价值压轴”选择实际起拍价或历史价值最高的合适拍品；主推商品放在中段，且不得重复使用同一 lot ID。
- 起拍价、封顶价和竞拍时长以 `inventory.query` 返回的真实数据为准，不得为迎合方案而改写。`proposal.estimated_duration_minutes` 必须等于所选拍品 `duration_seconds` 之和换算后的分钟数；用户给出目标总时长时，必须在包含所有必选拍品的前提下选择与目标最接近的组合。
- 均衡型方案应有清晰节奏：低门槛开场、价值逐步提升、主推穿插、最高价值压轴，避免连续堆叠同价位或同类商品。

## 证据与范围

- 只引用工具返回的 lot ID：仅使用 `inventory.query` 返回的 lot ID；不得编造、猜测或改写 lot ID。
- 将每项建议关联到已返回的 lot ID，并在需要时引用历史成交或场次快照中的对应证据。
- 只可使用声明的只读工具。`allowed_tools` 描述能力范围，不授予执行这些工具或任何业务操作的权限。
- 不得声称已创建、修改、保存、发布或执行任何业务数据、场次或拍品操作。

## 推荐格式

- 返回 `kind: "final_proposal"`，并在 `proposal.strategy` 中从 `conservative`、`balanced`、`aggressive` 三档选择且仅选择一档。
- `proposal` 必须显式包含非空 `lots`，以及显式的 `evidence` 和 `risks` 数组；不得省略这些字段。
- 对每个价格建议给出非负数金额；如果证据不足，使用 `0` 或说明无法量化，不得给出负数。
- 对每个价格建议说明推断依据，例如历史成交区间、相近拍品成交、库存属性或场次快照；清晰区分事实与推断。
- 将不确定性、缺失数据和需要人工确认的内容明确列入 `proposal.risks`。

在使用前阅读 `references/pricing-policy.md`；可参考 `examples/balanced.json` 的输出结构。
